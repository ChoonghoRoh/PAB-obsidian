# 단계 단위 — BUILDING [DS] (designer)

## 1. 하는 일

| 업무 | 산출물 |
|------|--------|
| 화면 시안 | HTML+CSS로 만든 화면(그림) — frontend-dev에게 넘김 |
| UI 설계 명세 | 화면 구조 · 상태별 UI · 디자인 토큰 · 컴포넌트 명세 |
| 디자인 트렌드 조사 | 조사 대상 · 비교 · 채택 제안 |
| 현행 디자인 검수 | 화면 · 요소 · 기준 · 제안을 한 줄씩 적은 지적 목록 |

## 2. 순서와 경계

- `[DS]` Task는 BUILDING에서 관련 `[FE]` Task보다 먼저 한다. `[FE]` Task는 `[DS]` 산출물을 입력으로 받는다.
- 제품 코드는 편집하지 않는다. 화면 시안(HTML+CSS)과 명세는 지시에서 정한 디자인 구역(`PROJECT.md` §3, 기본 `docs/design/`)에만 만들고 frontend-dev에게 넘긴다.

## 3. 완료 기준

- 화면 시안과 UI 설계 명세만으로 frontend-dev가 되묻지 않고 구현할 수 있어야 한다.
- 검수 지적은 화면 · 요소 · 기준 · 제안을 빠짐없이 적는다.
