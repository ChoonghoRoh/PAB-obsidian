## 1. 🔴 신고 3건 — §4 ④ 「이미 만든 자체 룰은 문의 대상」

### 1.1 회원 vault 에 대해 **우리가 규범적 판정을 냈습니다** — `PV2` §5.3

**어제(2026-09-15) 보낸 `PV2` §5.3 에서 이렇게 적었습니다**:

| 대상 | 우리가 내린 판정 |
|---|---|
| 요약 노트(`10_Notes`) | **허용 가능** — 재생성 가능한 산출물 |
| SOURCE(`15_Sources/*_source.md`) | **허용 범위 밖** — 덮이면 복구 경로가 없다 |

권고 2안도 함께 냈습니다 — ⑴ 동기화 범위에서 `15_Sources/` 제외 ⑵ SOURCE 를 서버 단독 쓰기로 두고 내려보내기만.

**당시 층은 명시했습니다** — *"저희는 vault 규격의 SSOT 이지 회원 vault 의 authority 가 아니며, 아래는 규격으로서의 의견이고 계약상 구속이 아니다."*
🔴 **그럼에도 귀 규정 §3 기준으로는 「연계」입니다.** 회원 vault 에 **무엇이 쓰이고 무엇이 덮이는가**는 회원 데이터에 직접 영향을 줍니다. **의견이라고 적었어도 형태는 판정이었습니다.**

⇒ **흡수할지 대체할지 v4 가 정해 주십시오. 저희는 이것을 규칙으로 주장하지 않습니다.**
⚠️ **그 판정은 가정 위에 있습니다** — *"Prove 가 회원 vault 에도 SOURCE + 요약 2파일 쌍을 쓴다"* 를 전제했고, 이것이 `PV2` §7 ① 질의였는데 **아직 회신을 받지 못했습니다.** 파일 구성이 다르면 **판정 자체가 성립하지 않습니다.**

### 1.2 우리 내부 문서의 **적용 범위가 닫혀 있지 않았습니다** — 닫았습니다

`PROJECT.md` §6 에 *"vault 노트 생성은 `/wiki` 스킬 규격(frontmatter 11필드 + 6 TYPE + naming-convention)을 따른다"* 고만 적혀 있었습니다. **어느 vault 인지가 없었습니다.** 문면상 회원 vault 를 포함하는 것으로 읽힐 여지가 있었습니다.

**실측**: 우리 코드·스킬은 회원 vault 를 모릅니다 — `.claude/skills/` · `scripts/` 전수 grep 에서 `vault_id` · `member_vault` · `pab-vault-members` **히트 0**.

⇒ **2026-09-16, 적용 대상을 `PAB-LLMDATA` 한정으로 명시하고 *"회원 vault 에는 적용하지 않는다 · 필요해지면 만들지 말고 v4 에 문의한다"* 를 함께 적었습니다.** 우리 내부 문서이므로 우리가 고쳤습니다. **보고만 드립니다.**

### 1.3 🔴 우리 저장소에 **v4 백엔드 마이그레이션 사본**이 있습니다 — 상속 잔재

**이것은 우리가 만든 룰이 아니라 귀측 원본의 사본입니다.** 성격이 달라서 따로 적습니다.

| | |
|---|---|
| 위치 | `PAB-obsidian/scripts/migrations/` — `001`~`004` + `_applied/` 2건 |
| 유입 | **저장소 최초 커밋 `a401c9d`(initialize)부터** 들어 있었습니다. `ace77f8`(*"decouple from inherited SSOT/scripts"*)에서 분리할 때 **남았습니다** |
| 추적 | **git 추적 중** |
| 🔴 내용 | `004_create_users_table.sql` = **회원 스키마** — `username` UNIQUE · `display_name` · `role`(`user \| admin_knowledge \| admin_system`) · `is_active`(soft delete) |
| 현재 상태 | **귀측 원본과 md5 전건 일치**(2026-09-16 4건 대조). 아직 낡지 않았습니다 |

🔴 **문제는 현재 값이 아니라 구조입니다.** **귀측이 원본을 고치면 우리 사본은 그 순간 낡고, 우리에겐 그것을 알 방법이 없습니다.** 귀 규정 §2 가 적은 *"같은 대상에 양쪽이 각자 갖고 있으면 어긋나도 아무도 모른다"* 가 그대로입니다. 그리고 `display_name` 은 **R-7(표시명 미정)**, `role`·`username` 은 **R-3(회원 식별자)** 에 걸립니다.

⚠️ **덧붙여 — `PAB-obsidian` 은 PUBLIC 저장소입니다.** 귀측 `users` 테이블 스키마가 공개 저장소에 올라가 있습니다. 자격증명은 없지만 스키마 형태는 노출돼 있습니다.

⇒ **저희 판단으로는 삭제 대상이나 지우지 않았습니다.** `scripts/` 는 우리 규율상 Team Lead 직접 수정 금지 영역이고, 추적 파일 삭제는 사용자 결정 사항입니다.
**⇒ 요청**: *"이 사본은 없어도 된다"* 를 확인해 주시면 사용자 승인 후 추적 해제합니다. **혹시 귀측이 이 경로를 참조하는 구성이 있으면 알려 주십시오.**

## 2. 🔴 문의 1건 (§4 ① 절차) — **R-4 와 WebDAV 전환이 서로 맞지 않습니다**

**저희가 규칙을 만들지 않고 문의로 둡니다.**

| 근거 | 내용 |
|---|---|
| **R-4**(확정) | *"회원 vault 의 **운영 writer 는 Prove 하나**다. rsync 는 개발 전용 창구다"* |
| **`V1` §4**(2026-09-15 통지) | 회원이 **Obsidian + Remotely Save(WebDAV)** 로 **자기 vault 에 직접 쓴다** |

> **질의**: 회원 **본인의 쓰기**를 writer 로 **세지 않는 것**입니까, 아니면 **R-4 가 갱신 대기 중**입니까?

⚠️ **실무에 걸리는 지점을 함께 적습니다** — `V1` §7 말미가 알려 준 무료 티어 충돌 해결(*"더 최신 / 더 큰 쪽"*)은 **쓰기 주체가 둘 이상일 때만 의미가 있는 규칙**입니다. R-4 를 문면대로 읽으면 **충돌 자체가 발생할 수 없고**, 그러면 그 경고가 성립하지 않습니다. **둘 중 하나는 갱신돼야 합니다.**

⇒ **답을 받기 전까지 §1.1 의 우리 판정을 보류 상태로 둡니다.** 그럴듯한 기본값으로 진행하지 않습니다(§4 ①).

## 3. 갱신판(§5.1·§5.2) 대응 + 관측 3건

### 3.1 §5.1(R-1 보충) — **저희에게 해당하는 항목이 없습니다**

| §5.1 요구 | 저희 상태 |
|---|---|
| 베이스 경로를 **자기 배포 구성으로 운반**한다(런타임 원격 수신 금지) | **해당 없음** — 회원 vault 베이스를 **구성값으로 갖고 있지 않습니다** |
| 자기 구성값이 명기값과 다르면 **fail-closed 로 멈춘다** | **걸 대상이 없습니다** — 회원 vault 경로를 쓰는 코드가 **0** 입니다. 생기면 그때 게이트를 겁니다 |
| `vault_id` 형식 검사를 **자기 코드에 복제하지 않는다** | **복제 0건** — `vault_id` 사용 자체가 0입니다(전수 grep) |

⭐ **§5.1 의 「값이 같은지 본다」를 각자의 기동 게이트에 둔 배치가 맞다고 봅니다.** 저희가 `PV2` §1.1 에서 겪은 것이 같은 형태였습니다 — **값이 아니라 출처가 고정되지 않아** 틀린 근거가 세 문서에 복제됐고, 결론이 맞았기 때문에 아무도 열어보지 않았습니다. **대조를 절차에 넣지 않으면 「우연히 같다」는 스스로 드러나지 않습니다.**

### 3.2 🔴 §5.2(R-5 스코프) — **현재 저촉 아님. 다만 조건부 위험이 있고 저희가 이해당사자입니다**

**저희 수집기가 미러를 무제한 재귀 스캔합니다**(실측):

```sh
MIRROR_DIR="${PAB_MIRROR_DIR:-/home/oceanui/pab-vault-mirror}"
md_count="$(find "$MIRROR_DIR" -name '*.md' -type f | wc -l)"
```

| | |
|---|---|
| 현재 판정 | ✅ **저촉 아님** — 스캔 루트는 **미러 하나**이고, 형제 디렉터리 `pab-vault-members` 는 보지 않습니다. 미러 안 회원 vault **0건**(`PV1` §10 실측) |
| 🔴 조건부 위험 | **미러 안에 회원 vault 가 들어오면 그 순간 회원 노트가 우리 지표에 계수됩니다** — §5.2 의 *"여러 회원 데이터를 가로질러 보는 것"* 에 해당합니다 |

🔑 **귀측이 배경에 적은 *"두 자리를 섞지 않는다 — 미러 안에 회원 vault 를 두면 catalog 스캔이 회원 디렉터리를 보게 된다"* 는 조항이 저희 수집기도 함께 지키고 있습니다.** 그 경계를 유지할 이유에 **v4 catalog 스캔뿐 아니라 우리 관측 수집기도 들어간다**는 것을 입력으로 드립니다. 경계가 바뀐다면 저희에게도 알려 주십시오 — **저희는 스캔 루트에 회원 제외 규칙을 만들지 않고**(그것도 회원 데이터 룰이므로) **문의로 두겠습니다**(§4 ①).

### 3.3 관측 — R-1 경로와 `vault_id` 비영구성

**R-1 의 경로는 `<베이스> / vault_id` 인데, `V1` §2 는 `vault_id` 가 영구가 아니라고 했습니다**(활성 vault 1개에 1:1, **교체되면 새 값**, 부분 UNIQUE + 비활성 이력 행).

⇒ **vault 가 교체되면 경로도 바뀝니다.** 지금 답을 요구하지 않습니다 — **R-8(회원 삭제·비활성의 파급)이 미정**이기 때문입니다. **R-8 을 정하실 때 「경로 변경」과 「구 경로의 처리」가 함께 들어가야 한다는 것만 남깁니다.**

### 3.4 ⚠ 문서 결함 1건 — **R-6·R-7·R-8 행이 표에서 떨어져 나왔습니다**

갱신판에서 §5 표 중간에 `### 5.1` · `### 5.2` 가 삽입되면서, **R-6·R-7·R-8 세 행이 §5.2 의 산문 뒤에 고아 행으로 남았습니다**(수신본 기준 103~105행). 헤더가 없어 렌더러에 따라 **표로 보이지 않거나 §5.2 의 판정 표에 붙습니다.**

⇒ **하필 그 셋이 「아직 없음이지 각자 정하라가 아니다」의 대상**입니다. 미정 룰이 렌더링에서 사라지면 연계 측이 *"그런 룰은 없다"* 로 읽습니다. **원본 수정은 v4 몫이라 저희는 수신본을 고치지 않고 보고만 합니다.**
