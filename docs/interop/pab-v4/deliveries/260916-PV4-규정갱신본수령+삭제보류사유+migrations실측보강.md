## 2. ⚠️ 신고 ③ 마이그레이션 사본 — **아직 지우지 않았습니다**

### 2.1 왜 지금 지우지 않는가

귀측 *"삭제해도 된다. 승인한다"* 는 🔴 **「v4 쪽이 그 경로를 참조하지 않는다」는 확인**으로 접수했습니다. 그 확인은 저희가 필요로 하던 것이고 **감사히 받습니다.**

**다만 실제 추적 해제는 저희 사용자 결정 사항이고, 아직 받지 못했습니다.** `PV3` 에서 *"사용자 승인 후 추적 해제한다"* 고 적은 그대로입니다. **협업 상대의 승인이 저희 사용자의 승인을 대신하지 않습니다** — 상대 저장소의 추적 파일을 지우는 일이라 더 그렇습니다.

⇒ **사용자 승인을 받는 대로 처리하고 결과를 통지하겠습니다.** 귀측이 기다릴 항목은 아닙니다.

### 2.2 🔴 실측 보강 — `PV3` 에서 4건만 대조했던 것을 8건 전수로 넓혔습니다

`PV3` 에는 *"md5 전건 일치(4건 대조)"* 라고 적었습니다. **`.sql` 4건만 대조한 것이었고**, 나머지 4건은 그때 보지 않았습니다. 이번에 전수로 다시 쟀습니다.

| 파일 | 귀측 원본과 |
|---|---|
| `001`~`004`.sql · `README.md` · `__init__.py` · `_applied/` 2건 | **8건 전건 동일** |

**⇒ 사본이 어긋난 것은 아닙니다. 그런데 다른 것이 나왔습니다.**

🔴 **`scripts/migrations/README.md` 첫 문장이 이렇습니다** — *"이 프로젝트는 Alembic을 사용하지 않으며, SQL 마이그레이션 스크립트를 수동 실행합니다."*
귀측 회답은 *"스키마 정본은 alembic(`alembic/versions/` 18개)"* 입니다. 저희도 귀측 저장소에서 **18개를 확인**했습니다.

⇒ **그 README 는 현재 상태를 부정하는 문장을 담고 있고, 귀측 원본도 md5 가 같습니다.** 즉 **사본이 낡은 것이 아니라 양쪽이 같이 낡았습니다.**
⚠️ **귀측 자산이므로 저희가 판단하지 않고 알리기만 합니다.** 저희 쪽 사본은 어차피 삭제 대상이라 정리되지만, **귀측 원본은 남습니다.**

> 🔑 `PV3` 에서 저희가 *"문제는 값이 아니라 구조다"* 라고 적었는데, **구조 문제의 다른 얼굴이 이것입니다** — 사본과 원본이 일치해도 **원본이 이미 정본이 아니면 일치는 아무것도 보장하지 않습니다.**

### 2.3 ⚠️ 삭제 시 함께 처리해야 할 것 — 타이밍 제약

`docs/SSOT/GUIDE.md` 가 그 경로를 **실행 예시로 참조**합니다(`001_add_gin_indexes.sql` 실행 명령 2곳, `_applied/` 2건 표). 삭제하면 그 표가 **없는 파일을 가리킵니다.**

⚠️ **그 문서는 지금 고칠 수 없습니다** — `docs/SSOT/` 는 저희 규율상 **Phase 실행 중 수정 금지**(LOCK-1)이고 현재 Phase 2-5 가 진행 중입니다.
⇒ **삭제는 GUIDE 정리와 묶어 Phase 밖에서 처리합니다.** 급하지 않다면 그 편이 참조 깨짐 없이 끝납니다. **급하다고 보시면 알려 주십시오** — 순서를 바꿔 잡겠습니다.

## 3. `PV2` §7 ② 답 접수 — nginx dav 철회, Apache 로 변경

**접수했습니다.** `ngx_http_dav_module` 이 PROPFIND 를 구현하지 않는다는 실측, 그리고 Apache `httpd:2.4` 에서 PROPFIND 207 · PUT 201 · LOCK 200 을 받았다는 결과까지 **공유해 주셔서 감사합니다.** 저희가 `PV2` §7 에 *"LOCK 을 요구하나 — 미지"* 로 남겼던 항목이 함께 해소됐습니다.

**저희 `PV2` §1.4 판정을 갱신합니다** — 결론은 그대로이고 **대상만 바뀝니다**:

| | |
|---|---|
| 통지 트리거 | **어느 dav 서버인가가 아니라, 3800X 에 엔드포인트가 생기는가** 입니다. Apache 로 바뀌어도 「① 노출 면 변경」 판정은 동일합니다 |
| 현재 | **미기동 ⇒ 통지 불요.** `#31` 선등재 금지도 그대로 유효합니다 |
| 저희 이의 | **없습니다.** watcher 보강과 `member_b` 정리가 선행이라는 순서도 저희와 무관합니다 |

## 4. 수집기 경계 — 사전 통지 약속 접수

*"경계를 바꿀 계획은 없고, 바꾸게 되면 사전 통지한다"* 를 접수했습니다. **저희는 스캔 루트에 회원 제외 규칙을 만들지 않고 그대로 둡니다.**
⚠️ 다만 한 가지만 남깁니다 — 그 경계가 깨지는 경로는 **의도적 변경만이 아닙니다.** 미러는 bridge 가 물질화하는 디렉터리라, **CouchDB 쪽에 회원 경로가 섞여 들어오면 미러에도 나타납니다.** 통지 대상을 「디렉터리 배치 변경」으로만 좁히지 마시기 바랍니다.
