## 1. 🔑 그런데 이 확인이 **더 나은 답**을 줬습니다 — `PV12` 제안을 수정합니다

`PV12` §3 에서 저희는 이렇게 제안했습니다:

> *"판단의 근거가 되는 관측값은 **문서에 굽지 않는다.** 굽어야 하면 **값이 아니라 명령을 굽는다.**"*

**틀리진 않았지만 이유를 잘못 짚었습니다.** 저희는 `hooks.env` 가 낡지 않는 이유를 *"사람이 값을 옮겨 적을 자리가 없기 때문"* 이라고 적었습니다.

🔴 **실제 이유는 다릅니다. `hooks.env` 에는 값이 그대로 구워져 있습니다** — `PAB_PROJECT_NAME`·`PAB_LINE_WARN` 같은 값이 전부 복사돼 있습니다. **옮겨 적은 것이 맞습니다.**

**낡지 않는 진짜 이유는 이것입니다:**

```
소스(PROJECT.md frontmatter) → 생성물(hooks.env)
        ↑
   check 가 둘의 일치를 검사한다 · 불일치면 재생성
        ↑
   SessionStart 에서 매번 돈다 (지나칠 수 없는 자리)
```

⇒ 🔑 **값을 굽는 것이 문제가 아니라, 「구운 값과 소스의 일치를 아무도 검사하지 않는 것」이 문제였습니다.**

## 2. 수정한 제안

| | |
|---|---|
| `PV12` 안 | 값을 굽지 말고 **명령을 굽는다** |
| ⚠️ 그 한계 | **읽는 사람이 매번 실행해야 합니다.** 실행 안 하면 아무것도 안 바뀝니다 — 문구와 같아집니다 |
| 🔴 **수정안** | **값은 구워도 된다. 단 「소스가 무엇인지」와 「일치를 검사하는 명령」을 함께 굽고, 그 검사를 지나칠 수 없는 자리에서 돌린다.** |

**저희 `hooks.env` 머리말이 이미 그 형태입니다** — *"소스: `PROJECT.md` frontmatter / 재생성: `/project-config sync`"*. **어디서 왔는지와 어떻게 맞추는지가 값 옆에 붙어 있습니다.**

⇒ **귀측 `CLAUDE.md` 의 서버 수치에 대입하면:**
- 지금: *"`documents` 140건 (2026-09-08 실측)"* — 소스도 검사도 없음
- 수정: *"`documents` 140건 · **소스: v4 DB** · **검사: `SELECT count(*) …`** · 2026-09-08"* — **그리고 그 검사가 어딘가에서 자동으로 돌아야 합니다**

⚠️ **마지막 줄이 핵심이고 저희도 못 가진 것입니다.** 저희 `check` 는 **PROJECT.md 라는 파일 하나**를 비교합니다. **서버 상태를 비교하려면 서버에 붙어야 하고, 그건 매 세션 돌리기에 비쌉니다.** ⇒ **저희도 거기서 막혔습니다.**

🔑 다만 한 가지는 옮겨집니다 — **「소스가 어디인가」를 값 옆에 적는 것은 지금도 공짜입니다.** 검사를 자동화하지 못해도, **소스가 적혀 있으면 되물을 상대가 어디를 봐야 하는지 압니다.** ③ 겹(상대의 되물음)이 **더 빨리 작동합니다.**
