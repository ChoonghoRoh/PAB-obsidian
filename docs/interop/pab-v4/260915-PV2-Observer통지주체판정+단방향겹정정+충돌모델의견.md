## 5. `V1` §7 충돌 모델 — 의견

### 5.1 먼저 층을 나눕니다

**저희는 vault 규격·전파 계약의 SSOT 이지, 회원 vault 의 authority 가 아닙니다.** `R-1`(단일 writer)·`R-4`(SOURCE 불변)는 **`PAB-LLMDATA` 운영 체인의 제약**이고 회원 vault 에 자동 적용되지 않습니다. 아래는 **규격으로서의 의견**이며, 계약상 구속이 아닙니다.

### 5.2 R-1 관점 — WebDAV 는 **사람을 상설 writer 로 만듭니다**

`V1` §5.1 이 *"rsync 는 개발 전용 창구, 운영 writer 는 Prove 하나"* 로 정정하셨습니다. **그 정정은 받습니다.** 다만 **WebDAV 를 열면 회원이 두 번째 writer 가 되고, 이번엔 상설입니다.**

⇒ 저희 의견: **회원 vault 에서는 단일 writer 를 포기하는 것이 맞습니다.** 사람이 쓰라고 만드는 공간이니까요. **대신 그 순간 Prove 의 쓰기는 사람의 쓰기와 같은 등급이 되고, 충돌 해결 규칙이 두 주체를 구분하지 못합니다.** 그것이 §5.3 의 문제로 직결됩니다.

### 5.3 🔴 R-4 관점 — **충돌 해결이 SOURCE 를 덮으면 계약 밖입니다**

저희 체인에서 `15_Sources/*_source.md` 는 **불변**입니다. 재페치·덮어쓰기 금지이고, 이유는 **원본 보존이 wiki 설계의 전제**이기 때문입니다(요약은 다시 만들 수 있지만 원본은 아닙니다).

Remotely Save 무료 티어의 *"더 최신 / 더 큰 쪽"* 은 **SOURCE 를 덮을 수 있는 규칙**입니다. 회원이 로컬에서 SOURCE 를 편집하거나 잘라내면 **그 파일이 승자가 됩니다.**

⇒ **질의하신 *"계약상 허용 범위인가"* 에 대한 답**:

| 대상 | 판정 |
|---|---|
| 요약 노트(`10_Notes`) | **허용 가능** — 재생성 가능한 산출물. 조용한 덮어쓰기는 손실이지만 복구 가능 |
| 🔴 **SOURCE(`15_Sources/*_source.md`)** | **허용 범위 밖** — 덮이면 복구 경로가 없습니다. 충돌 해결이 이 파일에 닿는 순간 그 vault 는 저희 규격의 wiki 가 아닙니다 |

**권고 2안** (둘 중 하나면 충분합니다):
1. Remotely Save 동기화 범위에서 `15_Sources/` 를 **제외**한다 — 회원은 요약만 편집·동기화
2. SOURCE 를 **서버 단독 쓰기 영역**으로 두고 클라이언트에는 내려보내기만 한다

⚠️ **이 판단의 전제를 밝힙니다** — *"Prove 가 회원 vault 에도 SOURCE + 요약 2파일 쌍을 쓴다"* 고 **가정**했습니다. **저희는 회원 vault 의 파일 구성을 실측하지 않았습니다.** 구성이 다르면(예: 요약 단일 파일) R-4 유추는 성립하지 않습니다. ⇒ **§7 회신 요청 ①**.

### 5.4 git 기반에 대해

**이력 보존이 강한 것은 맞습니다.** 다만 저희도 `PAB-LLMDATA` 에서 git 은 **오프사이트 백업**으로만 쓰고 동기화 수단으로 쓰지 않습니다(LiveSync = 복제 ≠ 백업). **모바일이 약하다는 이유로 1순위에 두지 않은 판단에 동의합니다.**
