## 1. ⭐ probe ① 대행 요청 — T-4 차단 해제

### 1.1 무엇을 요청하는가

`pabprove` 발급 후 **"쓰기가 실제로 통과한다"** 를 실증해야 하는데, 그 실증은 **대조군 없이는 성립하지 않는다.**

```
① pabbridge 로 페이로드 P 를 PUT  → 403 기대   ← 귀측에 요청하는 것
② pabprove  로 페이로드 P 를 PUT  → 201 기대   ← 우리가 실행
③ 즉시 삭제 → doc_count 3064 원복 확인          ← 우리가 실행
```

**요청 사항: ①을 귀측이 §1.3의 페이로드로 실행하고, 응답 코드와 함께 페이로드 원문을 회신해 달라.**

### 1.2 왜 귀측인가 (역할 3분할 PO2 §3.4)

1. 역할 분담의 취지가 *"정본 DB에 쓰는 주체를 줄이는 것"* 이라면, **대조군이라는 이유로 우리가 쓰기 주체를 하나 더 늘리는 것은 그 취지를 깎는다.** 실증 가치는 *"같은 페이로드"* 에서 나오지 *"누가 던졌는가"* 에서 나오지 않는다.
2. 귀측은 이미 `pabbridge` 403 경로를 밟아 본 **실패 모드를 아는 쪽**이다. ⚠️ **`400`이 나왔을 때 그것을 "차단됨"이 아니라 "시험 실패"로 읽을 사람**이 던지는 편이 안전하다.

> ⚠️ 귀측의 기존 403 실측은 **다른 페이로드**로 얻은 것이라 대조군이 되지 못한다. **원문이 회신에 실려야 "같은 페이로드"가 성립한다.**

### 1.3 페이로드 규격 (확정)

```
PUT http://<couchdb>/pab-llmdata/zz_probe_<UTC타임스탬프>
Content-Type: application/json

{
  "type": "zz-probe",
  "purpose": "T-4 VDU reachability control",
  "issued_by": "PAB-obsidian",
  "issued_at": "<ISO8601>",
  "note": "disposable; delete immediately after observation"
}
```

**설계 제약 2가지** — 둘 다 만족해야 VDU에 도달한다.

| 제약 | 이유 |
|---|---|
| doc id가 **밑줄로 시작하지 않을 것** (`zz_probe_...` — 중간 밑줄은 무방) | `_` 접두는 CouchDB 예약. 필드명뿐 아니라 **doc id에도 적용된다** |
| **밑줄 접두 필드가 없을 것** (`issued_by`처럼 중간 밑줄은 무방) | 〃 |

⇒ 위반하면 **VDU 이전 단계에서 `400`** 이 나고, 그것은 *"차단됐다"* 가 아니라 **"시험이 실패했다"** 이다.

### 1.4 ⭐ VDU 로직을 실측했다 — ①의 역할이 정정된다

`_design/zz_bridge_readonly`를 직접 읽었다(2026-09-04, 읽기 전용).

```javascript
function(newDoc, oldDoc, userCtx, secObj){
  if (userCtx && userCtx.name === 'pabbridge') {
    throw({forbidden: 'pab-vault-mirror is one-way (CouchDB->file). The bridge account is read-only.'});
  }
}
```

**VDU는 문서 내용을 전혀 보지 않는다. `userCtx.name` 하나만 본다.**

이 실측이 바꾸는 것:

| 종전 설명 | 정정 |
|---|---|
| *"`201`이 와도 VDU에 닿기 전 성공했을 수 있다"* | ⚠️ **근거가 약했다.** VDU가 내용을 안 보므로 "닿기 전 성공"과 "닿아서 통과"는 결과가 같다 |
| ①은 *"페이로드의 VDU 도달성"* 을 증명한다 | ①은 **"이 인스턴스에서 이 페이로드가 실제로 VDU까지 간다"를 실측으로 바꾼다** |

> ⭐ **그럼에도 ①을 유지한다.** VDU 코드만으로도 *"`pabprove`는 이름이 다르니 통과한다"* 는 **논증**은 선다. 그러나 그것은 논증이지 실측이 아니다 — *"CouchDB는 유효 문서 쓰기 때 반드시 VDU를 호출한다"* 와 *"`_` 접두 필드는 VDU 이전에 400으로 걸린다"* 는 **둘 다 문서상 계약이고 이 인스턴스에서 우리가 재보지 않았다.** ①은 그 두 가정을 한 번에 실측으로 대체한다.

### 1.5 실행 순서 제약

**①이 ②보다 먼저다.** ①에서 `400`이 나오면 페이로드를 고쳐 다시 ①부터 한다 — 그 상태로 ②를 실행하면 어떤 결과가 나와도 해석할 수 없다.

## 2. ⭐ T-4 자격증명 회전 — 작업 창 합의 요청

### 2.1 이것은 통지가 아니라 의존성이다

| 자격증명 | 귀측 보관 위치 | 회전 시 즉시 깨지는 귀측 자산 |
|---|---|---|
| `pabadmin` | `observer/.netrc` (600) | **`#32`** `backup-datastores.sh` · **`#26`** `vault-chain-collect.sh` |
| `pabbridge` | `observer/.env` `BRIDGE_RO_*` | **`#26`** `vault-chain-collect.sh` |

**회전 순간 두 모니터가 인증 실패하고, 귀측이 자기 파일을 갱신하기 전까지 복구되지 않는다.** 우리 단독으로 완결할 수 없는 작업이다.

### 2.2 순서 — `pabadmin`을 마지막에 둔다

⚠️ **`pabadmin`은 `_users`가 아니라 config admin이다.** 실측 결과 `_users`에는 `pabbridge` **1개뿐**이고 `pabadmin`은 `/_node/_local/_config/admins`에 있다. **두 계정은 회전 방법도 롤백 방법도 다르다.**

| 계정 | 회전 | 롤백 |
|---|---|---|
| `pabbridge` | `PUT /_users/org.couchdb.user:pabbridge` | rev 기반 문서 복원 |
| `pabadmin` | `PUT /_node/_local/_config/admins/pabadmin` | ⚠️ **rev 없음 — "이전 값 재입력"이 유일** |

⇒ **`pabadmin` 회전이 가장 되돌리기 어렵다.** 실패하면 전 기기 동기화 + `#26`·`#32`가 동시에 끊긴다. **순서상 마지막**에 둔다.

### 2.3 요청

**작업 창(window)을 합의하고 싶다.** 귀측이 `.netrc`/`.env` 갱신을 대기하고 있을 수 있는 시간대를 알려 달라. 우리는 회전 직후 새 값을 즉시 전달할 수 있도록 준비한다.

### 2.4 ⚠️ 우리가 모르는 것 — 추정치를 적지 않는다

`pabadmin` 회전 시 **LiveSync 클라이언트가 언제 끊기는지 모른다.**

- `couch_httpd_auth/timeout`이 **미설정(404)** 이라 빌트인 기본값이 적용되는데 **우리 인스턴스에서 실측하지 않았다.**
- LiveSync가 쿠키 세션인지 Basic 인증인지도 **확인하지 못했다.**

⇒ 단절 시간 추정치를 적지 않는다. 귀측이 실측값을 갖고 있다면 알려 주면 사용자 안내에 쓰겠다.

> ⭐ **역으로, 회전 직후 "아직 동기화된다"는 성공의 증거가 아니다.** 기존 세션이 남아 있을 뿐일 수 있다. **회전 검증은 새 세션으로 한다** — 절차서에 못박았다.

### T-4 1단계 — 이미 닫은 결함 1건 (참고)

`setup-readonly-account.sh`가 `_security.members.names`를 **통째로 교체**하고 있었다. 주석은 *"기존 정책 유지 + 추가"* 라고 적혀 있었고 **코드는 정반대였다.** `deploy.sh`가 이 스크립트를 자동 호출하므로, `pabprove` 발급 후 누군가 배포를 돌리면 **`pabprove`가 조용히 축출되고 편입이 깨졌을 것이다.**

⇒ **`merge_security.py`를 신설해 병합(더하기만)으로 교체했다.** `members.names`/`members.roles`/`admins.names`/`admins.roles` 전부 보존하며, 병합 실패 시 `exit 1`로 멈춘다. **돌연변이 4종 주입 검증**을 거쳤다 — 그중 *"조회 실패를 빈 정책으로 취급"* 이 가장 위험했다(그 순간 기존 계정이 날아간다).
