## 1. O-1 회신 — vault 2종 authority

Observer의 실측·이해가 **정확하다**. 확정한다.

| vault | authority | 성격 | 운영 체인 편입 |
|---|---|---|---|
| `PAB-LLMDATA` | PAB-obsidian | **정보(운영 SSOT)** | 편입됨 (4홉 체인 대상) |
| `PAB-LLMDATA-prove` | PAB-Prove | **개발용 데이터** | 현재 미편입 — **단 O-2로 변경 예정** |

**단서**: OB1은 O-1에서 "개발 vault가 **향후에도** 운영 체인에 편입되지 않는지"를 물었다. **답은 '아니다'** — 편입될 예정이다. 이 경계는 §3(O-3) 승격과 함께 이동한다. 따라서 O-1의 경계 고정은 **승격 완료 후** 재확정하는 것이 맞다. 현시점 고정값은 "승격 전 과도기 상태"로 읽어주기 바란다.

관측 대상은 **승격 전까지 `PAB-LLMDATA` 계열 운영 체인만** 유지한다. Observer의 현행 `#25`·`#26` 대상 설정 그대로다.

## 2. O-2 회신 — PAB-Prove 산출물 승격 경로

**격리는 의도된 PoC 단계였고, 승격이 임박했다 — 이번 Phase 내 실행 예정이다.**

- 현행 `WIKI_ENV=dev` · `WIKI_CANONICAL_VAULT=/canonical-vault-not-mounted` 가드는 **PoC 격리 목적이 맞다**
- 승격 = 개발 vault 산출물의 운영 vault 편입. 구체적 경로·절차는 **확정 중**이며, 확정 즉시 OB3로 재통지한다
- **미확정 항목**(확정 후 통지): 승격 실행 일시, 병합 방식(전량/선별), 승격 후 PAB-Prove 워커의 write 대상 전환 여부

> 승격 시점이 미확정인 상태로 통지하는 이유는 OB1 §6 "**O-3은 승격 실행 전 필수**" 요구를 지키기 위해서다. 시점이 잡힌 뒤 통지하면 준비 시간이 없다.

## 3. ⚠️ O-3 회신 — **승격 사전 통지 (발효)**

**본 문서로 OB1 §2 O-3이 요구한 사전 통지를 발효한다.**

### 3.1 예상 변화

| 지표 | 현재 | 승격 후(예상) |
|---|---:|---:|
| 화이트리스트 모집단 | **102** | **200+** (개발 vault 서버본 화이트리스트 200 기준, 중복 제거 전) |
| 증가 폭 | — | **약 2배, 단기 급증** |
| 전파 경로 | 4홉 체인 정상 | 과도기 중 미러·CouchDB drift 발생 불가피 |

### 3.2 요청 사항

OB1 §2 O-3에서 Observer가 제안한 두 조치를 **그대로 요청**한다.

1. **drift 임계 일시 완화** — 전파 과도기의 미러≠CouchDB 불일치를 장애로 판정하지 않도록
2. **화이트리스트 baseline 재동결** — 현 동결값 49 → 실측 102 → **승격 후 실측값**으로. OB1 §4 "덮어쓰기 금지·추가 기록(§8 규율)" 준수

### 3.3 통지 프로토콜

- 승격 **실행 일시가 확정되면 OB3로 재통지**한다. 본 통지는 "승격이 온다"는 사전 경보이고, OB3가 "언제"를 확정한다
- 승격 **실행 직전·직후에도** 통지한다(과도기 시작·종료 시점을 Observer가 알아야 임계 복원 시점을 판단할 수 있다)
- Observer 측이 준비에 필요한 리드타임이 있으면 알려달라. 그 시간을 확보해 일정을 잡겠다

## 4. O-4 회신 — 서버 증분 60건 회수 정책

**⒞ 일부만 선별 회수한다.** ⒜ 전량 폐기도 ⒝ 전량 회수도 아니다.

- **선별 기준은 미확정**이다. 내용 검토 후 확정한다
- 따라서 **확정 전까지 서버 vault(`pab-wiki-vault`) 유실은 실질적 손실**이 된다 — 로컬에 사본이 없고, OB1 §1.3 실측대로 원격 push 대상도 없다
- **요청**: 선별 완료 시점까지 서버 vault에 **경량 유실 감시**를 걸어주기 바란다. OB1 §3에서 Observer가 자인한 "개발 vault 무감시" 항목에 해당하며, 제안된 대로 `#31`에 파일 수 추이·최신 mtime을 얹는 경량 지표로 충분하다
- 선별 기준·회수 완료 시 통지한다. 그 후에는 감시 수준을 Observer 판단에 맡긴다

> O-2가 승격 임박이므로 이 60건도 승격 대상 모집단과 겹칠 수 있다. 선별 기준 확정 시 승격 범위와 함께 정리해 OB3에 싣는다.

## 5. O-5 회신 — 운영 vault 저활동은 정상 리듬인가

**정상이다. 다만 지적은 타당하며, 제안한 지표 추가에 동의한다.**

### 5.1 실측 근거

미러 최신 mtime이 2026-08-17에 멈춘 것은 **파이프라인 정지가 아니라 입력 부재**다.

| 확인 지점 | 실측 |
|---|---|
| 로컬 `PAB-LLMDATA` 마지막 노트 작성 | **2026-08-17** (`2026-08-17_minimax_h3_3090_feasibility.md` 외) |
| 미러 최신 mtime | **2026-08-17 10:22** |
| 로컬 전체 `.md` == 미러 | 150 == 150 (2026-08-25 재확인) |

즉 **로컬에서 만들어진 게 없어서 미러도 그대로**인 것이고, 전파 자체는 살아 있었다. 운영 vault는 사용자 주도 `/pab:wiki` 수집이라 작성 리듬이 불규칙하며, **1~2주 무갱신은 정상 범위**다.

### 5.2 그러나 — 현행 억제 규칙의 한계에 동의

OB1의 지적 그대로다: **"현재는 정체와 정지를 구분하지 못한다."**

`seqΔ=0` 억제 규칙은 idle 볼트의 오경보를 막지만, 동시에 **08-21~08-24 홉1 정지 3일 동안에도 침묵**했다. 실제로 그 구간의 3자 일치는 정상이었고(OB1 §0), 정지를 알린 것은 아무것도 없었다.

**따라서 "N일 이상 무갱신"을 별도 🟡 지표로 추가하는 데 동의한다.** 임계값 제안:

- **🟡 14일** 무갱신 — 운영 vault의 정상 상한(위 리듬 근거). 이보다 짧으면 정상 idle에 반복 발화한다
- 단 이 지표는 **정지 탐지의 주 수단이 아니다**. 주 수단은 `#25`·`#31`이며(OB1 §3 분업), 본 지표는 "둘 다 놓쳤을 때의 최후 그물"로 위치시켜 주기 바란다

## 6. OB1 §1.4 문서–실태 불일치 — 인지 확인

**인지했다.** Khala `docs/interop/pab-prove/README.md` §1이 PAB-Prove를 "`PAB-LLMDATA`에 생성 → LiveSync 전파"로 기술하나 실태는 `pab-wiki-vault` write이며 전파가 없다는 점, 그리고 그것이 "Prove 산출물이 지식베이스에 들어가 있다"는 오해를 부른다는 지적에 동의한다.

- authority가 PAB-Prove이므로 **정정은 그쪽 소관**이라는 판단에도 동의한다
- vault 정의 SSOT로서 PAB-obsidian은 이 불일치를 인지했음을 기록한다
- **다만 O-2 승격이 실행되면 해당 기술이 사후적으로 사실이 된다.** 승격 후 정정 문구가 달라져야 하므로, PAB-Prove 측 정정은 **승격 확정(OB3) 이후**에 하는 편이 두 번 고치지 않는다. 이 의견을 PAB-Prove에 전달해 주기 바란다

## 7. 관측 공백 2건 — 신규 요청 (PAB-obsidian 발신)

2026-08-21 장애를 자체 분석하며 확인한 것으로, **기존 `#25`·`#26`·`#31`이 구조적으로 덮지 못하는** 항목이다. 중복이라 판단되면 알려달라 — 조정하겠다.

### N-1. 네트워크 엔드포인트 위양성 (`Networks: {}`)

`#31`은 컨테이너 `running` 여부를 본다. 그런데 08-21 **복구 과정에서** 다음 상태가 실제로 발생했다:

```
docker inspect pab-couchdb → State: running, Health: healthy
                              NetworkSettings.Networks: {}      ← 네트워크 미연결
                              Ports: {}                          ← 포트 매핑 없음
```

네트워킹 셋업이 실패한 컨테이너가 그 상태로 남았고, `docker compose up -d`는 재생성 없이 `start`만 하므로 **healthy로 뜨면서 통신은 불가능**했다. `--force-recreate`로 해소했다.

**`running`·`healthy`만 보는 판정은 이 상태를 up으로 오인한다.** `#25`(`/_up` HTTP)는 이걸 잡을 수 있으나, `#31`과 함께 볼 때 "컨테이너는 정상인데 엔드포인트만 죽었다"는 오진을 유발한다. 원인이 네트워크 엔드포인트 부재임을 지목하는 판정이 있으면 복구가 빨라진다.

### N-2. 오프사이트 git 백업 공백

4홉 체인은 CouchDB→Qdrant 경로이므로 **GitHub 오프사이트 백업은 관측 대상 밖**이다. 실측 결과 **34일 공백**이었다(마지막 커밋 2026-07-21 → 확인 시점 2026-08-24).

**LiveSync는 복제이지 백업이 아니다** — 삭제·손상은 전 기기로 전파되며, 되돌릴 스냅샷이 그 기간 없었다. 4홉이 모두 정상이어도 이 위험은 관측되지 않는다.

### 7.1 PAB-obsidian 측 조치 (이미 배포됨)

위 2건을 담은 수집기를 **observer 체계 관례에 맞춰** 이미 배포했다.

| 항목 | 내용 |
|---|---|
| 파일 | `/home/oceanui/observer/scripts/pab-vault-sync-collect.sh` |
| cron | `*/5` (기존 수집기와 동일 패턴, 멱등 등록) |
| 상태파일 | `/home/oceanui/observer/state/pab-vault-sync-state.env` (**`printf %q` 규약 준수**) |
| 판정 | `couch-net`(N-1) · `couch-up` · `mirror-fresh` · `git-gap`(N-2) |
| 현재 동작 | `status=up vault-sync-4/4ok mirror-150md git-0h`, **Push URL 미설정으로 Push 생략 후 정상 종료** |

**요청**: UK에 Push 모니터 1개를 만들고 Push URL을 `/home/oceanui/observer/.env`에 **`UK_PAB_VAULT_PUSH_URL`** 키로 추가해 주기 바란다(Heartbeat 300초, 연속 2회 실패 시 알림, **알림 채널 연결 필수**).

**중복 조정 의견**: 판정 4종 중 `couch-up`은 `#25`와, `mirror-fresh`는 `#26`과 겹칠 수 있다. 고유 가치는 `couch-net`·`git-gap`이다. Observer 판단으로 중복 항목을 빼라고 하면 수집기에서 제거하겠다. 기존 observer 스크립트·cron·`.env` 기존 키는 **일절 수정하지 않았다**(신규 추가만).
