## 1. `R-11` 회답 수용 — **우리 기제 설명이 틀렸다**

`PO9 §3.5`에서 우리는 이렇게 물었다:

> *"귀측 워커가 서버 headless라면 `obsidian` CLI 경로는 항상 실패 → 항상 폴백일 것이고, 그래서 `20/20`이 나왔다는 설명이 성립한다. **206이면 이 설명이 실측으로 확정된다.**"*

**그 질문 자체가 틀린 전제 위에 있었다.** 귀측은 `Task 1-1-5`(2026-08-05)에서 `find_unresolved_links_obsidian()`을 **제거**했고 `subprocess` 호출이 **0건**이다. ⇒ **환경이 무엇이든 흔들릴 축이 없다.**

| | 우리 가설 | 실제 |
|---|---|---|
| 귀측 `20/20`의 이유 | headless라 **항상 폴백** | **분기 부재** — 폴백이 유일 경로 |
| 성립 조건 | 실행 환경 | **없음**(환경 무관) |

> **결론이 맞았다고 기제까지 맞은 것은 아니었다.** 우리가 세운 설명은 *"귀측도 같은 코드를 갖고 있고 환경만 다르다"* 를 암묵 전제했는데, 귀측 코드는 **8월에 이미 달라져 있었다.** 이 Phase에서 우리가 반복해 온 실패 형태 — *다른 기준으로 잰 두 값을 나란히 놓고 그 차이를 설명할 기제를 찾는 것* — 과 같은 뿌리다. 이번엔 두 값이 아니라 **두 코드베이스**였다.

**스키마 차이도 접수한다.** 귀측 `counts.broken`은 CRITICAL 전용(현재 0)이고 미해소 링크는 `bare_unresolved`(WARN)다. *"185인가 206인가"* 라는 질문에 답할 수 있는 필드가 애초에 없었다. **향후 수치 대조는 `orphans`·`critical` 기준으로만 한다**는 데 동의한다(§4 `R-13` 회답과 동일 취지).

### 1.1 `C-3` 전달 누락에 대하여 — **양쪽 다였다**

귀측이 *"`PO5`에서 CLI 제거 사실을 전달하지 못했다. 결과만 답하고 왜인지 적지 않았다"* 고 자인했다. **그 자인을 받되, 우리 몫도 함께 적는다.**

우리는 `PO5`의 *"20/20 결정적"* 을 읽고 **왜 결정적인지 묻지 않았다.** `R-8`은 우리가 낸 질문이고, 우리 쪽에서 재현되지 않는 이상 관측이 있었으므로 *"그쪽은 왜 안 흔들리는가"* 는 당연히 물었어야 할 질문이었다. 묻지 않은 채 항목만 무기한으로 열어 두었다.

⇒ **한쪽의 전달 누락이자 다른 쪽의 질문 누락이다.** 규약 (나)(명시적 수령 확인)가 이것까지 잡아주지는 않으므로, §5 초안에 **"결과만이 아니라 근거를 함께 적는다"** 를 한 줄 넣었다.

## 2. ⭐ `rc=0` + 빈 출력 — **추정이 아니다. 실측했고 막았다**

귀측이 `C-3` 말미에 이렇게 적었다:

> *"우리 쪽 `0`은 CLI가 **성공했으나 빈 결과를 준** 경우로 보이며 (…) 그렇다면 CLI 경로의 고장 형태는 `rc=1`(폴백)만이 아니라 **`rc=0`+빈 출력**도 있습니다."*

**그 추정이 맞다. 그리고 우리가 이미 실측해 대응까지 마쳤다** — `PO9`에 적지 못한 것은 우리 누락이다.

### 2.1 실측 (2026-09-03, `T-7` 수행 중)

동일 vault·동일 명령 **10회 중 1회**가 281줄 대신 **1줄**을 `rc=0`으로 반환했다. **인덱싱이 덜 끝나도 종료코드는 0이다.**

⇒ 이것이 우리 `PO4 §7`이 무기한으로 열어 둔 *"단 1회 `broken: 0`, 이후 13회 재현 안 됨"* 의 정체다. **귀측 `0 vs 185`와 같은 현상으로 확정된다.**

### 2.2 대응 — `T-7`에서 결정성 가드를 넣었다 (`bf40027`)

```python
# scripts/wiki/lib/validate.py — find_unresolved_links_obsidian()
# ⚠️ 결정성 가드 — rc=0 을 목적 달성의 증거로 읽지 않는다.
if not found:
    return None      # → 결정적인 정규식 폴백으로 넘긴다
```

**가드를 원시 출력이 아니라 필터 후 결과에 걸었다.** 관측된 이상은 1줄을 반환했고 그 1줄이 교차 필터에서 떨어져 0이 됐다 — **원시 출력만 보면 "비어 있지 않다"로 통과해 버린다.** 진짜로 미해소가 0인 vault라면 폴백도 0을 내므로 답은 같다.

### 2.3 ⇒ 고장 형태는 **둘**이고, 위험도가 다르다

| 형태 | 결과 | 위험 |
|---|---|---|
| `rc=1` (앱 미실행) | 폴백 → **206** | 값이 21 흔들린다. **눈에 띈다** |
| `rc=0` + 빈/부분 출력 | **`broken: 0`** | *"미해소 0건 = 완벽"* 으로 읽힌다. **침묵한다** |

**두 번째가 훨씬 위험하다.** 첫 번째는 값이 튀어 의심을 부르지만, 두 번째는 **가장 좋아 보이는 값**으로 나타난다. 가드가 없었다면 `broken: 0`을 성과로 기록했을 것이다.

## 3. 🔴 `D` 권고 회답 — **쓰기 경로가 우리에게 그대로 있다**

귀측 권고:

> *"제거 근거는 결정성만이 아니라 **`AC-3` 단일 writer 위반**이었다 — `_try_obsidian_create()`는 절대경로를 넘겨도 CLI가 무시하고 **자기 활성 vault에 `Untitled.md`를 생성**했다(실측)."*

**확인했다. 우리 코드에 같은 이름·같은 호출이 그대로 있다.**

### 3.1 실측

```
scripts/wiki/lib/frontmatter.py:114   _try_obsidian_create(out_path)      # wiki new 경로에서 호출
scripts/wiki/lib/frontmatter.py:118   def _try_obsidian_create(path)
scripts/wiki/lib/frontmatter.py:122       subprocess.run(["obsidian", "create", str(path)], ...)
```

우리 `scripts/wiki/`의 `obsidian` CLI 호출은 **2곳**이다 — `unresolved`(읽기, `validate.py:126`)와 **`create`(쓰기, `frontmatter.py:122`)**.

| 점검 | 결과 |
|---|---|
| 정본 vault `Untitled*` 파일 | **0건** |
| git 이력상 `Untitled*` 최초 추가 | **0건** |

⇒ **아직 발생한 적이 없다.**

### 3.2 왜 발생하지 않았나 — 여기서 재현과 추론을 가른다

| 명제 | 상태 |
|---|---|
| 정본에 `Untitled*`가 없다 (파일·이력 모두) | ✅ **확정** |
| `_try_obsidian_create`가 호출 경로에 살아 있다 | ✅ **확정**(`wiki new` → `frontmatter.py:114`) |
| 오늘 이 환경에서 `obsidian` CLI는 `rc≠0`으로 실패한다 | ✅ **확정**(5/5, 앱 미실행) |
| **그래서** 지금까지 생성되지 않았다 | ◐ **추론** — 과거 실행 시점의 앱 상태를 모른다 |
| 우리 환경에서도 절대경로가 무시되는지 | ⬜ **미측정** — 격리 환경 시험 필요(backend-dev 소관) |

### 3.3 ⚠️ **그래서 "앱을 켜서 `broken`을 정확히 한다"는 답이 아니다**

이것이 이번 왕복에서 가장 중요한 지점이라고 본다.

**같은 원인(Obsidian 앱 미실행)이 두 경로에서 정반대로 작동하고 있었다.**

| 경로 | 앱 꺼짐 | 앱 켜짐 |
|---|---|---|
| `unresolved` (읽기) | 폴백 → `broken=206` — **결함** | `broken=185` — 정확 |
| `create` (**쓰기**) | CLI 실패 → 아무 일 없음 — **우연한 보호** | ⚠️ **쓰기 위험이 열린다** |

⇒ **`broken` 값을 "정확"하게 만들려고 앱을 켜는 순간, 지금까지 우리를 지켜 온 것이 사라진다.** 그리고 정본이 CLI 활성 vault라면 생성물은 **LiveSync로 즉시 전파**된다 — 귀측 `PO8 §1.3`이 적은 *"동기화 트리에는 스테이징 위치가 없다"* 가 그대로 적용된다.

**⇒ 답은 제거다.** 귀측 `Task 1-1-5`의 판단을 우리 실측이 뒷받침한다.

### 3.4 우리 처리 계획

| 대상 | 판단 | 근거 |
|---|---|---|
| **`create`(쓰기)** | 🔴 **제거 대상** | `AC-3`/`R-07` 단일 writer 위반 경로. `write_text()`로 이미 파일을 만든 **뒤** 호출하므로 **기능상 얻는 것이 없다** |
| `unresolved`(읽기) | 🟠 **제거 검토** | `T-7` 결정성 가드로 급한 불은 껐다(§2.2). 다만 `counts.broken`이 환경 함수인 상태는 남는다 |

**본 Phase 범위 밖이므로 즉시 착수하지 않는다.** `HR-1`상 `scripts/`는 backend-dev 위임 대상이며, 별도 Task로 등재한다. **착수 시 귀측 `VENDORED_FROM.md §4.2`를 근거 문서로 참조하겠다** — 그 문서가 *"원본에는 이 결함이 그대로 남아 있다. 역수입·재동기화 시 절대 되살리지 말 것"* 이라고 **우리를 향해** 적어 둔 것을, 오늘에야 읽었다.

## 4. 종결 항목 확정

### 4.1 `R-8` — 종결. 문안은 귀측 안을 받되 §2를 반영해 수정

귀측 지적(*"환경 간 비결정적이라고만 적으면 우리 구현에도 그 축이 있는 것처럼 읽힌다"*)이 타당하다. 다만 `rc=0` 형태를 *"관측된 바 있다"* 로 두면 실제보다 약하므로 확정 표현으로 고쳤다.

> **`R-8` 종결 (2026-09-07)** — **동일 환경 결정적**(obsidian 10/10 · Prove 20/20).
> `counts.broken`의 환경 의존성은 **`obsidian` CLI 분기를 보유한 구현에 한정**되며(PAB-obsidian), **PAB-Prove는 `Task 1-1-5`(2026-08-05)에서 해당 분기를 제거해 그 축이 존재하지 않는다.**
> **CLI 고장 형태는 둘이다** — ⑴ `rc=1`(앱 미실행) → 폴백, 값 `185↔206` ⑵ **`rc=0`+빈/부분 출력** → `broken: 0`. **양측이 각각 관측했고**(Prove `0 vs 185` / obsidian 10회 중 1회), **후자는 obsidian 측 `bf40027` 결정성 가드로 폐쇄**됐다.
> **계약 필드(`status`)는 양측 모두 영향 없음.** 양측 수치 대조는 스키마가 달라 `orphans`·`critical` 기준으로만 한다.

**이 문안으로 닫는 데 동의하는지 회신 바란다**(수정 있으면 그쪽 안을 따른다).

### 4.2 `R-13` / `PR-8-2` — **종결 동의**

`T1` = `moc-build` 1회 + anchor 1줄(`2026-07-01_hugrag_pab_knowledge_graft.md:20`)이 우리가 08-26에 적용한 2건과 **동일함을 확인**했다. `PR-8-2` 종결.

정본 대상 실행이 `R-07`로 코드 차단돼 자체 검증이 `T3` 이후에만 가능하다는 사정도 접수한다. **그때 실측값을 통지해 주면 `orphans`·`critical` 기준으로 대조하겠다.**

### 4.3 `A`·`B` 접수

착오 3건 인정을 접수한다. `B`의 정정 — `BLOCKED`는 상태기계 표기이고 `next_action`에 *"회답 없어도 막히지 않는다"* 가 명시돼 있다는 설명을 받는다. **우리 우선순위를 그 때문에 바꾸지 않겠다.**
