# Interop Hub — PAB-obsidian ↔ 외부 협업 공간

> **목적**: PAB-obsidian(wiki vault·LiveSync 전파 계약)과 외부 프로젝트 사이의 **계약 문서·조율 상태**를 한 곳에서 관리한다.
> **표준**: Khala `docs/interop/README.md` 허브 헌장의 SSOT 규약·배지 규약을 준용한다(PAB 프로젝트 간 형식 통일).
> **생성**: 2026-08-24 (PAB-Observer 발신 계약 수신으로 개설)

## 규약 (요지)

1. **SSOT 명시**: 협업 문서 상단에 authority 배지를 단다.
2. **무왜곡 사본**: 수신본은 수정하지 않는다. 갱신은 원본 authority가 수행 → 재전달.
3. **브레이킹 통지**: vault 구조·화이트리스트 범위·전파 경로 변경은 상대에 **사전 통지**.

## 채널 규약 (PAB-obsidian ↔ PAB-Prove 공통 · 2026-09-07 합의)

> `PO10 §5` 초안 → `PO11 §3` 전건 채택. **양측 동일 문안**이며 PAB-Prove `docs/interop/README.md §2`에 같은 내용이 있다.
> ⚠️ 현재는 **PAB-Prove 채널 한정**이다. PAB-Observer 채널로의 확대는 별도 합의 사항.

### 전달
- 문서는 **양측 저장소에 대칭 배치**한다. 발신자가 자기 저장소의 채널 디렉토리와 상대 저장소의 채널 디렉토리 양쪽에 배치한다. 수신본은 커밋하지 않는다.
- 배치 직후 **SendMessage로 1줄 고지**를 병행한다. 상대 세션이 죽어 있어도 파일이 남으므로 손실은 없다 — 고지는 도달 시각을 앞당기는 장치일 뿐이다.

### 수령
- **수신자의 명시적 표명**(회신 문서 또는 SendMessage)이 있어야 전달 완료다. md5 대조는 수신 세션의 생존을 전제하므로 완료 조건으로 쓰지 않는다.

### 채번
- **발신 시점에 매긴다.** 미래 번호를 예약해 부르지 않는다.
- 미확정 문서는 **성격으로만 참조**한다(예: "편입 실행 통지"). `PO-next` 류의 표기도 슬롯 예약이므로 쓰지 않는다 — 두 문서가 동시에 자기를 next로 부르면 같은 충돌이 난다.
- **동시 채번 충돌**: 같은 번호가 생기면 **발신자 자기 저장소의 커밋 시각이 이른 쪽**이 그 번호를 갖고, 늦은 쪽이 **다음 번호로 재채번**한다. 재채번 문서는 머리말에 사실과 판정 근거(양측 커밋 시각)를 남긴다. 이미 배치·고지된 문서는 건드리지 않는다.
- 위반·충돌 이력: `PO4→PO5` 예약(obsidian) · `PO7→PO8` 예약(Prove) · **`PO10` 동시 채번**(2026-09-07 — 위반이 아니라 **규약의 공백**. 실측 09:19:20 `11ecd40` vs 09:25:51 `6048926`). 각 1회씩.

### 내용
- 회답에는 **결과만이 아니라 근거를 함께 적는다.** *"20/20 결정적"* 은 정확했으나 *"분기를 제거해서"* 가 빠져 상대가 같은 결함을 한 달 더 안고 갔다(`R-8`, 2026-08~09). **정확한 회답이 유용한 회답은 아니다.**
