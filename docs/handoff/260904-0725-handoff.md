#### ⑴ `pabadmin`은 `_users`가 아니라 **config admin**이다

`_users`에는 `pabbridge` **1개뿐**이고 `pabadmin`은 `/_node/_local/_config/admins`에 있다. **두 계정의 회전 방법이 서로 다르다** — 하나로 묶어 절차를 짜면 실패한다.

| 계정 | 회전 | 롤백 |
|---|---|---|
| `pabadmin` | `PUT /_node/_local/_config/admins/pabadmin` | ⚠️ **rev 없음 — "이전 값 재입력"뿐** |
| `pabbridge` | `PUT /_users/org.couchdb.user:pabbridge` | rev 기반 문서 복원 가능 |

⇒ **`pabadmin` 회전이 가장 되돌리기 어렵다.** 실패하면 전 기기 동기화 + Observer `#26`·`#32`가 동시에 끊긴다. **순서상 마지막**에 둔다.

#### ⑵ `_security.members.names = ["pabbridge"]` — `pabprove`는 여기 없으면 **읽기도 안 된다**

members가 비어있지 않으므로 목록 밖 계정은 접근 자체가 막힌다. **VDU 통과 이전 문제**다.

#### ⑶ 🔴 `setup-readonly-account.sh`가 `pabprove`를 **조용히 축출한다**

```bash
# :45  주석 — "기존 _admin 멤버 정책 유지 + bridge 사용자/롤 추가"
curl -sf -X PUT ".../_security" -d "{...\"names\":[\"${BRIDGE_USER}\"]...}"   # ← names 통째 교체
```

**주석은 "유지 + 추가", 코드는 "교체"다.** 그리고 **`deploy.sh`가 이 스크립트를 자동 호출한다.**

⇒ `pabprove` 발급 후 누군가 `deploy.sh`를 돌리면 — bridge 설정 변경이든 `pabbridge` 회전이든 — **`pabprove`가 `_security`에서 사라지고 편입이 조용히 깨진다.** 주석을 믿고 읽으면 절대 안 보인다.

**⇒ `pabprove` 발급 전에 members 보존형으로 고치는 것이 선결 조건이다.** (`pab-vault-cloud/`는 `code_dirs` 밖이나 backend-dev 편집 허용으로 판정 — HR-1은 Team Lead의 편집을 막는 규칙이지 backend-dev의 범위를 정하는 규칙이 아니다.)

#### 🔴 Observer 통지는 예의가 아니라 **하드 의존성**이다

| 자격증명 | 보관 | 사용하는 Observer 자산 |
|---|---|---|
| `pabadmin` | `observer/.netrc` (600) | **`#32`** `backup-datastores.sh` · **`#26`** `vault-chain-collect.sh` (+ 우리 T-3 볼륨백업) |
| `pabbridge` | `observer/.env` `BRIDGE_RO_*` | **`#26`** `vault-chain-collect.sh` |

**회전 순간 `#26`·`#32`가 즉시 인증 실패**하고, Observer가 자기 파일을 갱신하지 않으면 복구되지 않는다. **양측 동시 작업이 필요한 회전**이다.

> ⚠️ backend-dev 초안은 회전 게이트를 `PR-1`만으로 보아 *"지금 가능"* 이라 했으나 **좁다.** 같은 보고 §3이 Observer 하드 의존성을 밝히고 있어 **§3과 §4 표가 서로 어긋난다 — §3이 맞다.** 회전은 **Observer 조율이 끝나야 가능**하다.

#### probe 설계 — `201`을 통과의 증거로 쓰지 않는다

```
페이로드: doc id = zz_probe_<ts> (밑줄로 시작 안 함) + 밑줄 접두 필드 없음
① 같은 페이로드를 pabbridge 로 PUT → 403 기대
     ⇒ "이 페이로드는 VDU 까지 도달한다"가 증명된다 (400 이면 시험 실패)
② 같은 페이로드를 pabprove 로 PUT  → 201 기대
     ⇒ ①로 도달성이 증명됐으므로 201 = "도달했고 이름으로 갈려 통과했다"
③ 즉시 삭제 → doc_count 3064 원복 확인
```

**①이 없으면 ②의 `201`은 "VDU에 닿지도 않았는데 성공"과 구분되지 않는다.** Observer의 기존 403 실측은 **다른 페이로드**라 대조군이 못 된다.

⚠️ ①은 역할 3분할(PO2 §3.4)상 Observer 몫과 겹친다. **OB2-E에서 합의 후 실행.** 두 안: ⒜ 우리가 대조군 1회 실행(통지) ⒝ **Observer가 우리 페이로드로 ①을 대신 실행**하고 회신 — **⒝가 역할 분담에 맞다.**
