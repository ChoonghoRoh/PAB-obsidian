### 6.2 이 세션에서 반복된 실패 형태 (8회)

**계기가 가리킨 값을 목적 달성의 증거로 읽는 것.**

| 오독 | 실제 |
|---|---|
| `tar exit 0` = 백업 성공 | append-only라 rc=1이 정상. **아카이브 무결성**을 봐야 한다 |
| `HTTP 400` = 쓰기 차단됨 | VDU 이전에 반려된 것 = **시험 실패** |
| design doc 존재 = VDU 복원됨 | **함수 본문 194자**까지 봐야 한다 |
| 조용한 `git status` = 문제 없음 | `skip-worktree`가 증상만 가리고 있었다 |
| `git check-ignore` 0건 = 이상 없음 | `--no-index` 없이는 **인덱스 파일을 안 본다** |
| 시험 4종 통과 = 가드 동작 | 전부 한쪽 분기만 탔다(G9) |
| `orphans=0` = MOC 정상 | TYPES·DOMAINS만 보고 **TOPIC 정체는 안 본다** |
| 지침에 적어둠 = 지켜짐 | **부작위 요구는 리뷰에 안 보인다** → 회귀 시험으로 |

⚠️ **내가 낸 오류 중 최악은 `broken 206`이었다.** 존재하지 않는 값을 계약 문서(PO2)에 적었고, **그 차이에 "MOC 정비로 21건 해소"라는 그럴듯한 설명까지 붙였다.** `git worktree`로 구 코드×구 vault를 재현해서야 확정됐다 — **"지금 안 그렇다"가 아니라 "그때도 그랬다"를 보여야 확정된다.**

⇒ **결론이 맞으면 근거를 검증하지 않는 경향**이 양쪽에 있다. 이 세션에서 잡힌 것 열 건 남짓 중 **혼자 찾을 수 있었을 것은 없다.** 전부 상대의 다른 조건·다른 코드베이스에서 나왔다. HR-6은 "더 유능한 사람이 본다"가 아니라 **"다른 사람이 다른 조건으로 돌려본다"**에 가깝다.
