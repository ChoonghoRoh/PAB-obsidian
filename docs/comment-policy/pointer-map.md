# 포인터 맵

> 코드에 흩어진 `point-N` 을 한 표로 본다. 내용은 각 프로젝트의 검증 리포트에 있다.
> 생성·갱신 `python3 scripts/comment/comment-lint.py map <경로>`
> 조회 `python3 scripts/comment/comment-lint.py show point-N`(읽기 전용 역할은 `--no-record` 추가)

---

## 열 규격

| 열 | 유지 주체 | 설명 |
|---|---|---|
| **point** | 사람 | `point-N` · 순증 · 재사용 금지. 리포트 항목으로 링크한다 |
| **설명** | 사람 | 한 줄. **5단어 이내** 권장. 수치·수식 금지 |
| **연결 파일** | 🔧 **도구** | `map` 이 코드를 훑어 다시 쓴다. 손으로 고치지 않는다 |
| **작성일** | 사람 | `YYMMDD`. 리포트 항목을 처음 쓴 날 |
| **수정일** | 사람 | `YYMMDD`. 리포트 항목 내용을 고친 날. 없으면 `-` |
| **최근 조회** | 🔧 **도구** | `show` 가 찍는다. 손으로 적지 않는다 |

🔴 **도구 열을 손으로 고치지 않는다.** 손으로 유지하는 날짜는 낡는다. `연결 파일` 은 코드가 정본이고 `최근 조회` 는 조회 행위가 정본이다.

### 연결 파일 표기

`파일:행` 을 가운뎃점으로 잇는다. **3곳을 넘으면 앞 3곳 + `외 N곳`** 으로 줄인다.

```
src/DateInput.tsx:24 · src/Form.tsx:88 · src/Filter.tsx:12 · 외 2곳
```

### 최근 조회의 뜻

**누군가 이 항목을 실제로 열어 봤다**는 기록이다. 마지막 수정일과 다르다. 수정일은 글이 바뀐 날이고 조회일은 쓸모가 확인된 날이다.

조회가 오래 없는 항목은 둘 중 하나다. 이미 해소됐거나, 아무도 안 보는데 남아 있거나. **정리 후보를 고르는 신호로만 쓴다.** 조회가 없다고 자동으로 지우지 않는다.

## 상태 표기

| 표기 | 뜻 | 처리 |
|:-:|---|---|
| — | 정상 | |
| 🔴 | **죽은 참조** — 코드가 가리키는데 리포트에 항목이 없다 | 항목을 쓰거나 참조를 지운다 |
| 🟡 | **고아** — 리포트에 있는데 코드가 안 가리킨다 | 해소됐으면 결번 처리, 아니면 참조를 붙인다 |
| ⬜ | **결번** — 지운 번호 | 그대로 둔다. 재사용 금지 |
