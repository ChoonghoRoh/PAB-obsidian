> **베이스**: COMMENT-1(주석 최소화 — `docs/SSOT/WORKFLOW/handoff/common.md §5`). 하네스 · scratchpad 임시 도구에 적용되는 최소 원칙.

## 1. 주석 작성 규칙

주석은 **코드의 역할과 작동 방식만** 최소로 적는다. 설명하지 않는다.

### 1.1 형식

> 규칙 ID: **NOTE-1**(형식) · **NOTE-4**(닫는 표지 — 판정은 §4.2)

```
Name : 한글명 · 작성일
Name : 한글명 · 작성일/수정일
Name : 한글명 · 작성일 · point-N
```

| 확장자 | 여는 표지 | 닫는 표지 |
|---|---|---|
| `.html` | `<!-- Header : 헤더 · 260918 -->` | `<!-- // Header -->` |
| `.jsx` `.tsx` | `{/* Header : 헤더 · 260918 */}` | `{/* // Header */}` |
| `.js` `.ts` | `// Header : 헤더 · 260918` | `// // Header` |
| `.css` `.scss` | `/* Header : 헤더 · 260918 */` | `/* // Header */` |
| `.sh` `.py` | `# Header : 헤더 · 260918` | `# // Header` |

- **영문명** — 검색 키다. `[A-Za-z][A-Za-z0-9]*`. 같은 블록은 파일 전체에서 같은 이름을 쓴다.
- **한글명** — **최대 5단어.**
- **날짜** — `YYMMDD`. 수정이 없으면 작성일 하나만 적는다.
- **구분자** — 가운뎃점 `·` 고정.

### 1.2 예시

```html
<!-- Header : 헤더 · 260918 -->
<!-- // Header -->

<!-- Nav : 네비게이션 · 260918 -->
<!-- // Nav -->

<!-- SubTitle : 서브타이틀 · 260918 -->
<!-- // SubTitle -->

<!-- RightPanel : 우측 패널 · 260918/260920 -->
<!-- // RightPanel -->

<!-- AlertArea : 알림 영역 · 260918 -->
<!-- // AlertArea -->

<!-- SaveBtn : 저장 클릭시 실행 · 260918 -->
```

### 1.3 금지

> 규칙 ID: **NOTE-2**

**수치·수식·개수는 적지 않는다.** 대상이 바뀌면 조용히 틀려지고 빌드도 검사도 잡지 못한다.

```
❌  <!-- CardList : 카드 12개 · 260918 -->
❌  <!-- Token : 연결 86건 · 260918 -->
❌  <!-- Grid : 폭 240px 고정 · 260918 -->
✅  <!-- CardList : 카드 목록 · 260918 -->
```

설명도 적지 않는다.

```
❌  <!-- Header : 로고와 내비를 포함하며 스크롤 시 고정됩니다 · 260918 -->
✅  <!-- Header : 헤더 · 260918 -->
```

이력도 적지 않는다. 결함 번호·Phase 번호·버전은 **검증 리포트로 보낸다**(§2).

```
❌  <!-- Guard : DEF-9-7 수정분 · 260918 -->
✅  <!-- Guard : 입력 검증 · 260918 · point-12 -->
```

개발 과정 · 이슈도 적지 않는다. 무엇을 시도했고 무엇이 문제였는지는 **검증 리포트로 보낸다**(§2).

```
❌  <!-- Modal : 스크롤 잠금 이슈로 재작성 · 260918 -->
✅  <!-- Modal : 모달 · 260918 · point-13 -->
```

주석 안에 코드 예시를 적지 않는다. 검사가 주석 속 코드를 실제 코드로 읽어 오판한다. 예시는 `point-N` 리포트에 둔다.

```
❌  // Fetch : if (res.ok) { return res.json(); } · 260918
✅  // Fetch : 응답 파싱 · 260918 · point-14
```

### 1.4 순번은 허용한다

> 규칙 ID: **NOTE-3**

순번은 **개수를 주장하지 않고 어느 것인지만 가리킨다.** 개수가 바뀌어도 거짓이 되지 않는다.

```
✅  <!-- Carousel1 : 캐러셀 1 · 260918 -->
✅  <!-- TabCont1 : 탭 콘텐츠 1 · 260918 -->
✅  <!-- TabCont2 : 탭 콘텐츠 2 · 260918 -->
```

🔴 **삭제해도 번호를 당기지 않는다. 결번을 둔다.**
`TabCont2`를 지웠다고 `TabCont3`을 2로 바꾸면 검증 리포트의 참조가 전부 어긋난다.

```
TabCont1 · TabCont3 · TabCont4      ← 2는 결번. 정상이다
```

### 1.5 붙이는 자리

**기능 컴포넌트 단위**에 붙인다. 레이아웃 래퍼(`<div class="row">`)와 반복 렌더링되는 행 안쪽에는 붙이지 않는다.

| 영문 | 한글 |
|---|---|
| `Header` | 헤더 |
| `Nav` | 네비게이션 |
| `SubTitle` | 서브타이틀 |
| `Search` | 조회 영역 |
| `List` | 목록 영역 |
| `Content` | 콘텐츠 영역 |
| `Form` | 입력 영역 |
| `Tab` / `TabCont{N}` | 탭 / 탭 콘텐츠 |
| `RightPanel` | 우측 패널 |
| `AlertArea` | 알림 영역 |
| `Button` | 버튼 영역 |
| `Paging` | 페이징 |
| `Modal` | 팝업 |
| `Carousel{N}` | 캐러셀 |

중첩은 허용한다. 대신 **닫는 표지를 예외 없이** 둔다. 깊어질수록 닫는 표지가 유일한 경계 신호다.

```html
<!-- Tab : 탭 · 260918 -->
  <!-- TabCont1 : 기본 정보 · 260918 -->
    <!-- Search : 조회 영역 · 260918 -->
    <!-- // Search -->
    <!-- List : 목록 영역 · 260918 -->
    <!-- // List -->
  <!-- // TabCont1 -->
<!-- // Tab -->
```

## 2. 포인터 운영

> 규칙 ID: **NOTE-6**

### 2.1 언제 쓰나

**오류에 의한 참고가 필요할 때만** 쓴다. 그 외에는 쓰지 않는다.

- 이 방식을 쓰면 안 되는 이유
- 거부한 대안
- 사고 이력에서 나온 제약
- 파인튜닝 계열의 결론

### 2.2 코드 쪽

식별자만 붙인다. 내용은 적지 않는다.

```html
<!-- DateInput : 날짜 입력 · 260918 · point-12 -->
```

### 2.3 리포트 쪽

`docs/comment-policy/points/` 에 **한 항목 한 파일**로 둔다. 파일명은 `point-{번호}-{주제어}.md` 다.

한 파일에 모으지 않는 이유는 **하나를 보려고 전체를 읽게 되기 때문**이다. 파일을 가르면 조회가 그 파일 하나로 끝나고, `ls points/` 만으로 주제 목록이 나온다.

주제어는 한 낱말로 붙인다. 포인터만 보고 따라갈지 고를 수 있어야 한다. 번호만 있으면 열어봐야 알고 그러면 전부 열거나 전부 무시하게 된다.

```markdown
# point-12 · 날짜 입력 형식 검증          ← points/point-12-날짜파싱.md

- **일자** 260918
- **수정** -
- **무엇** `Date.parse` 를 쓰지 않는다
- **왜** 브라우저마다 결과가 달라 같은 입력이 다른 값이 된다
- **대신** 형식을 명시해 파싱한다
- **버린 안** 정규식 사전 검증 — 지역 형식에서 통과율이 떨어졌다
```

🔴 **현재 값을 적지 않는다.** 코드가 바뀌면 거짓이 된다. 계열과 이유만 적는다.

```
❌  임계값은 현재 0.5다
✅  0.3(과검출) → 0.7(누락) → 0.5 채택. 2026-09-08 측정, 샘플 200
```

### 2.4 번호

`point-N` 은 순증한다. **재사용하지 않는다.** 항목을 지워도 번호는 결번으로 둔다.

## 3. 기존 주석 처리

| 현재 상태 | 처리 |
|---|---|
| 설명형 | 규격 표지로 **교체** |
| 수치 포함 | 수치를 **빼고** 교체 |
| 이력 서술 | 리포트로 **이관** 후 `point-N` 참조로 교체 |
| 규격 표지인데 닫는 표지 없음 | 닫는 표지 **추가** |
| 의도·판단 서술 | 리포트로 이관. 이관 대상이 아니면 **삭제** |
| 주석 안의 코드 예시 | 리포트로 **이관**하거나 **삭제** |

한꺼번에 정리하지 않는다. 개선·추가 개발로 **건드리는 블록만** 이 표대로 바꾸고(COMMENT-2), 남은 규모는 `scan` 으로 재고 부채 레지스트리에 둔다. COMMENT-2는 제품 코드 구역(`PROJECT.md` §3)의 주석에 적용한다. 구역 밖 하네스는 COMMENT-1만 따른다.

**건드린 블록** = 변경 줄을 품은 가장 안쪽 규격 블록 + 여는 · 닫는 표지 줄 자체가 바뀐 블록.

**판정 범위(COMMENT-2)**: 적용 기준은 작성자가 아니라 파일 위치다 — 제품 코드 구역(`PROJECT.md` §3)의 주석에 적용한다. 구역 밖 하네스는 COMMENT-1만 따른다. `lint <대상> --changed <기준 커밋>` 위반 0이 기준이며 위반이 있으면 결함이다. 파일 전체 위반 수가 부채 레지스트리 기준선보다 늘어도 결함이다 — 등급은 `ROLES/SUB-SSOT/VERIFIER/verification-procedure.md`(이하 VP) §G2 판정 기준 「등급 산출」 표. 기준 커밋은 Task 지시에 적는다. 비교 단위는 대상 파일이 속한 부채 레지스트리 행이다 — 경로 행이면 `lint <행 경로>` 위반 합계를 그 행의 「lint 위반」 기준선과 비교하고, 그 파일의 파일 행이 있으면 파일 행을 쓴다. 보고 대상은 건드린 블록 안의 위반과, 블록 밖이라도 변경 줄 위의 위반이다. 바깥 블록의 직접 줄(자식 블록 밖)을 고치면 바깥 블록이 건드린 블록이 되므로 그 안 자식 블록의 위반까지 보고된다 — 파일 전체를 감싸는 블록의 직접 줄을 고치면 사실상 파일 전체 검사가 된다.

순서는 이렇게 간다.

1. `scan` 으로 기준선을 뜬다
2. 이력 서술을 리포트로 옮기고 `point-N` 을 붙인다
3. 나머지를 규격 표지로 교체한다
4. `lint` 로 잔여를 확인한다
5. `points` 로 참조를 대조한다

### 3.1 예외 — 주석 전체 정리 게이트 (COMMENT-3)

사용자가 파일을 지정해 요청하면 그 파일의 주석 전체를 정리한다. 발동 · 편성 · 판정 기준은 COMMENT-3(`docs/SSOT/WORKFLOW/handoff/common.md` §5)이고, 요청 기록 · 기준선 · 레지스트리는 Team Lead가 한다(`docs/SSOT/ROLES/SUB-SSOT/TEAM-LEAD/orchestration-procedure.md` §업무 지시 규약). 담당 dev는 이렇게 한다.

1. Team Lead가 task 파일에 적은 기준선(`lint <파일>` 위반 수 · `scan <파일>` 분류 수)을 확인한다
2. 파일 전체 주석을 위 표대로 규격으로 바꾸고, 의도 · 이력 서술은 `point-N` 으로 옮긴다
3. 완료 판단: `lint <파일>` 위반 0 · `points <파일>` 죽은 참조 0 · 새로 옮긴 `point-N`이 `points <root>`에서 고아로 남지 않음 · 정리 중 지운 기존 `point-N` 참조가 고아가 되지 않음(diff 삭제 줄의 `point-N` 을 고아 목록과 대조) · `map` 갱신 · 주석 외 변경 0
4. 주석 전용 커밋으로 넘긴다 — 기능 변경을 섞지 않는다

## 4. 하네스

```bash
python3 scripts/comment/comment-lint.py scan   <경로>
python3 scripts/comment/comment-lint.py lint   <경로> [--check-date] [--changed <rev>]
python3 scripts/comment/comment-lint.py points <경로> [--points <디렉터리>]
python3 scripts/comment/comment-lint.py map    <경로>
python3 scripts/comment/comment-lint.py show   point-N [--no-record]
```

### 4.1 `scan` — 기준선

주석 총계와 분류를 센다. 교체 대상 규모를 잡을 때 쓴다.

```
대상 파일      28개
주석 총계      1048건
  판정 제외    31건  3.0%
  코드 예시    9건  0.9%     ← 제거 · point-N 이관 대상
  규격 표지    0건  0.0%
  설명형       412건  39.3%   ← 교체 대상
  금지 수치    77건  7.3%     ← 제거 대상
  이력 서술    85건  8.1%     ← 리포트 이관 대상
```

### 4.2 `lint` — 규격 위반

| 코드 | 무엇 |
|---|---|
| `L1` | 규격 불일치 — 구분자·날짜 누락, 날짜 아님 |
| `L2` | 한글명 5단어 초과 |
| `L3` | 금지 수치 · 순번 외 숫자 |
| `L4` | 표지 짝 불일치 — 안 닫힘 / 여는 표지 없이 닫음 / 이름 어긋남 |
| `L5` | 수정일자 stale — 주석 날짜가 git 최종 수정일보다 이르다 (`--check-date`) |
| `L7` | 설명형 잔존 — 서술 어미 또는 길이 초과 |
| `L8` | 주석 내 코드 예시 — 규격 파싱 전에 격리해 표지 짝 판정(`L4`)에 넣지 않는다 |

`L4` 는 스택으로 판정한다(NOTE-4). 개수만 세면 중첩에서 틀린다.

`lint <대상> --changed <rev>` 는 `git diff -U0 <rev>`(작업 트리 기준)의 변경 줄로 건드린 블록(§3)을 정해 그 범위의 위반만 보고한다. 추적 안 된 새 파일은 전체를 본다. `--check-date` 와 함께 쓰면 `L5` 도 건드린 블록에만 건다. `<rev>` 를 해석할 수 없거나 git 밖이면 종료 2, 위반 0이면 0, 있으면 1이다. `--changed` 가 없으면 파일 전체를 본다.

출력 머리 「변경 줄 M줄」의 M은 이번 판정 대상 파일의 변경 줄만 센다 — `walk` 가 실제로 낸 파일(root가 파일이면 그 파일 하나, 디렉터리면 판정 확장자이면서 제외 디렉터리 밖의 파일)과 변경 파일(추적 안 된 새 파일 포함)의 교집합이다. diff 머리(`--- ` · `+++ `)는 파일 머리 구간(`diff --git` 뒤, 첫 `@@` 앞)에서만 읽어, 본문 줄 `-- …` · `++ …` 를 파일 경로로 오인하지 않는다. 없는 경로는 `--changed` 여부와 무관하게 git 조회 전에 종료 2(`오류 — 없는 경로: <root>`), root가 판정 확장자가 아닌 파일(`.md` 등)이면 종료 2(`오류 — 판정 대상 아님(확장자 <ext>): <root>`)다.

### 4.3 `points` — 포인터 대조

| 신호 | 무엇 |
|---|---|
| 🔴 죽은 참조 | 코드가 가리키는데 리포트에 없다 |
| 🟡 고아 항목 | 리포트에 있는데 코드가 안 가리킨다 |

죽은 참조가 있으면 종료 코드 1을 낸다.

### 4.4 `map` — 포인터 맵 갱신

[pointer-map.md](pointer-map.md) 의 **연결 파일** 열을 코드에서 다시 쓰고, 항목 링크를 `points/` 실제 파일로 건다. 설명·작성일·수정일·최근 조회는 보존한다. 죽은 참조는 🔴, 고아는 🟡 로 설명 끝에 표시한다.

🔴 **연결 파일 열을 손으로 고치지 않는다.** 코드가 정본이다.

### 4.5 `show` — 항목 조회

해당 **파일 하나만** 읽어 출력하고 맵의 **최근 조회** 를 오늘 날짜로 찍는다. `points/` 를 통째로 열지 않는다. 읽기 전용 역할(verifier · planner — EDIT-4, 파일 쓰기 없음)은 `--no-record`를 붙여 맵 갱신 없이 조회한다.

```bash
python3 scripts/comment/comment-lint.py show point-12
python3 scripts/comment/comment-lint.py show point-12 --no-record   # 읽기 전용 역할
```

🔴 **최근 조회를 손으로 적지 않는다.** 조회 행위가 정본이다. 손으로 유지하는 날짜는 낡는다.

조회가 오래 없는 항목은 이미 해소됐거나 아무도 안 보는 것이다. **정리 후보를 고르는 신호로만 쓰고 자동으로 지우지 않는다.**

## 5. 이 규칙이 잡지 못하는 것

- **의도 서술의 정확성** — 코드로 표현할 수 없고 기계로 틀렸는지 알 수 없다. 리포트로 옮긴 뒤에는 **정확성을 관리하지 않는다.** 틀려도 두고 거기에 시간을 쓰지 않는다.
- **수정일자를 사람이 유지하는가** — `--check-date` 가 어긋남을 잡지만 고치는 것은 사람이다.
- **포인터가 가리키는 내용이 맞는가** — 존재 여부만 검사된다. 링크는 살아 있는데 내용이 틀린 상태는 잡지 못한다.
- **`--changed` 의 한계**
  - 삭제만 있는 hunk 는 변경 줄을 만들지 않는다 — 표지 줄만 지우면 `L4`(짝 불일치)를 놓친다. 표지를 지운 파일은 `lint <파일>`(`--changed` 없이)로 본다 — 지운 표지 때문에 생긴 `L4` 도 결함이고(등급은 VP §G2 판정 기준 「등급 산출」 표), 나머지 위반은 레지스트리 기준선과 비교하는 COMMENT-2 판정을 따른다(COMMENT-3 게이트 밖이므로 파일 전체 lint 위반을 결함으로 올리지 않는다)
  - 이름 바뀐 파일은 내용 변경이 없으면(순수 개명) 검사하지 않는다
  - `--changed` 없이 `--check-date` 를 쓰면 `L5` 가 파일 전체에 걸린다
  - 파일명에 `"` · `\` · 제어문자가 들어 있으면 git 이 따옴표로 감싸 내보내 그 파일이 빠진다
- **대상 파일 없는 디렉터리** — 디렉터리 root 아래에 판정 대상 파일이 하나도 없으면 「위반 0건」 · 종료 0이다. 판정 근거로 쓰기 전에 대상 경로를 확인한다

## 6. 읽을 때

> 규칙 ID: **NOTE-5**

§1 쓸 때와 짝을 이루는 절이다.

**주석으로 결론을 내지 않는다.** 주석은 어디를 볼지 정하는 재료다.

| 단계 | 근거 | 낼 수 있는 결론 |
|---|---|---|
| L1 | 주석·파일명 | 🔴 **없음.** 위치만 정한다 |
| L2 | `point-N` 항목 | 금지 사유·설계 근거 인용 |
| L3 | 코드 흐름 | 현재 상태·값·분기 조건 |

공용 값(PK·설정·권한 플래그)과 분기 조건은 **L3 필수**다. 설계·검수·검증은 **L3 → L2 → L1** 순으로 본다. 주석을 먼저 읽으면 코드를 그 해석으로 읽게 된다.

🔴 **L3 결론과 주석이 어긋나면 그 자체가 결함이다.** 조용히 넘어가지 않는다.

**NOTE-5 판정**: 읽는 쪽 규칙이라 `lint` 대상이 아니다. verifier가 G2에서 판독으로 본다 — 결론의 근거가 L3에 있는가, 주석만 근거로 결론을 내지 않았는가, L3 결론과 주석이 어긋난 곳을 결함으로 적었는가. 위반은 결함이다 — 등급은 VP §G2 판정 기준 「등급 산출」 표(§7).

## 7. 우선순위

**동작에 영향이 있는가**로 먼저 가른다. 주석 규격 NOTE-1~6 위반도 같은 기준이다 — 등급은 VP §G2 판정 기준 「등급 산출」 표로 매긴다(동작 영향이 없으면 대개 Low).

| 성격 | 예 | 처리 |
|---|---|---|
| **동작** | 빌드 실패·렌더 깨짐·죽은 링크·타입 오류 | **즉시** |
| **NOTE 위반** | NOTE-1~6 규격 위반 (형식·금지 수치·결번·닫는 표지·읽기 3단계·point-N) | **보고하고 그 Task에서 고친다.** 등급은 VP §G2 판정 기준 「등급 산출」 표 — Low면 게이트를 막지 않는다 |
| **그 밖의 글자** | 오탈자·표현 다듬기 | **모아서 한 번에.** 단독으로 턴을 쓰지 않는다 |

🔴 **NOTE-1~6 위반은 보고 대상이다.** 그 밖의 글자 오류는 메모만 하고 이어간다.
🔴 검사가 실패하면 통과시키기 전에 묻는다 — **「이 검사는 무엇을 막으려고 만들어졌나?」** 걸린 것이 그 목적에 해당하지 않으면 검사를 고친다.
