## 1. 왜 이 공간인가

세션·저장소가 나뉘어 협업할 때 계약을 안 쓰면 ① 규칙·근거가 상대에 도달하지 못하고 ② 무엇이 원본인지 흩어지고 ③ 되돌리기 기준점을 잃는다. 이 공간은 그 셋을 파일로 고정한다.

## 2. SSOT 규정 (협업 원칙)

1. **단일 원본** — 각 협업 문서는 authority 가 **정확히 하나**. 반대편의 같은 문서는 **읽기전용 사본**.
2. **방향 명시** — 모든 협업 문서 상단에 **SSOT 배지**(전달본/공유본 · authority · 최종 동기화일).
3. **무왜곡 사본** — 사본은 원본을 고치지 않는다. 갱신은 authority 가 하고 상대에 **재전달**한다.
4. **브레이킹 통지 (하드 게이트)** — 계약 브레이킹(경로·컴포넌트 props·배럴 export·토큰 이름/값·스타일 import 순서·어댑터 시그니처) 변경은 사전 통지 + 짝문서 동시 갱신 + **양측 반영 전 다음 Task 착수 금지**.
5. **경계 불변** — 아래 §3 레지스트리를 따른다. 상대 관할을 침범하지 않는다.

## 4. 동기화 프로토콜

### 4.1 상대 → 나 (소스 하달)
- 이 세션은 상대 저장소를 **자동으로 못 본다.** 필요한 것은 **경로 + 커밋 해시 + 필요한 대목**을 지시서에 실제로 붙인다.
- 상대 소스를 소비할 때는 상대 경로를 **직접 읽는다**(읽기전용 참조).

### 4.2 나 → 상대 (회신·통지)
- 상대 문서를 고칠 일이 생기면 **고치지 말고** 상대 `docs/interop/<이 저장소 slug>/inbox.md` 에 한 줄 **append**(same-machine · 과거 항목 불변 · "상대 repo 수정 금지"의 명시적 예외). 다른 머신이면 SendMessage 통지 → 수신측이 자기 inbox 갱신.
- 소스를 **소비 중**임을 통지해, 상대가 그 baseline 을 흔들지 않게 한다(**freeze**).

### 4.3 공통
- 계약 브레이킹은 양측 동시 반영 전까지 다음 작업 착수 금지.
- 상대 보존 영역은 이쪽이 수정하지 않는다. 읽기만.
- 완료·상태 신호는 **실측**(build/lint/tsc 0 · route 200 · git A/M/D 집계).
